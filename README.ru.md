# 🐉 AI Dungeon Master

[English](README.md) | Русский

Локальный мастер для текстовых ролевых игр в браузере. Вы описываете действие, модель отвечает от лица мастера. Приложение работает с любой LLM через OpenAI-совместимый API (по умолчанию — [LM Studio](http://localhost:1234)).

Страницу можно открыть на этом компьютере, на телефоне в той же сети Wi-Fi или на устройстве в той же сети Tailscale.

Если играете на русском, хорошо подходят модели Gemma 4: они уверенно пишут по-русски и дают нормальное соотношение размера и качества. Обычно хватает 31B или 26B A4B.

Старая настольная программа лежит в [AIDM_Desktop](AIDM_Desktop/README.ru.md). Текущая версия — эта, браузерная.

## Возможности

- **Текстовая сессия** — ход игрока и ответ мастера, с потоковой генерацией
- **Миры** — отдельная папка на кампанию: файлы, история, карточки и память
- **Карточки историй** — заметки с триггерами; подходящие карточки попадают в промпт сами
- **Банк памяти** — модель индексирует прошедшие ходы и подставляет нужные воспоминания
- **Суммаризация** — сжатие хроники в `summary.txt`, когда новая история заполняет контекст
- **Остановка генерации** — можно прервать ответ, суммаризацию, память, промпт сцены или описание карточки
- **Промпт сцены** — текст и антипромпт для генерации картинки по последним ходам
- **Конфигурации моделей** — несколько API сохраняются и переключаются кнопкой **Модели**
- **Два языка интерфейса** — русский и английский; список миров делится по языку кампании
- **Экспорт мира** — zip с файлами одной кампании, без настроек программы

## Релиз

1. Из корня репозитория запустите `build_web.ps1`.
2. Скрипт соберёт `App_web/`: внутри `AIDM.exe` и пустая папка `worlds/` рядом с ним.
3. Упакуйте `App_web` в zip и распакуйте архив в любую папку.
4. Запустите `AIDM.exe`.
5. Выберите, откуда открывать игру: только этот компьютер, домашний Wi-Fi или Tailscale.
6. Окно консоли не закрывайте. Если закрыть его, сервер остановится.
7. Запустите локальную модель. По умолчанию игра ждёт [LM Studio](http://localhost:1234).

Миры, созданные в программе, сохраняются в `worlds` рядом с `AIDM.exe`. Эта папка уезжает вместе с архивом. Сборка не копирует уже существующие кампании и ключи API: `worlds/settings.json` в архиве — пустой шаблон.

## Запуск из исходников

```text
pip install -r requirements.txt
python run_web.py
```

При запуске из исходников миры остаются в `worlds` в корне репозитория. Рядом с программой они лежат только у собранного exe.

## Сеть

Первое окно спрашивает, откуда открывать игру. Выбор запоминается в `worlds/settings.json` (`bind_mode`).

| Вариант | Кто откроет страницу |
|---------|----------------------|
| Только этот компьютер | Этот ПК, адрес `http://127.0.0.1:8765` |
| Домашняя сеть Wi-Fi | Устройства в той же сети Wi-Fi. Адрес показан в окне. |
| Tailscale | Устройства в той же сети Tailscale. Tailscale должен быть запущен до нажатия «Запустить». Общий Wi-Fi не нужен. |

Сервер занимает порт **8765**. Если телефон не открывает страницу, разрешите входящий TCP 8765 в брандмауэре Windows. Компьютер должен оставаться включённым.

Те же адреса видны в **Настройки**: этот компьютер, телефон и Tailscale, если сеть найдена. Галочка «Открыть игру для локальной сети» запоминается там. Чтобы новый адрес начал открываться, сервер нужно перезапустить. Режим Tailscale выбирается в первом окне при запуске.

## Быстрый старт

1. Запустите модель и сервер игры.
2. На странице откройте **Миры** и создайте мир. В репозитории уже есть примеры в `Demo worlds`.
3. В **Файлы** заполните инструкции ИИ, основы сюжета, авторские пометки и вступление.
4. При желании добавьте **Карточки**.
5. Напишите действие и нажмите **Отправить**. На узком экране поле ввода открывается кнопкой **Сделать ход**.
6. В **Настройки** подстройте адрес API, температуру, размер контекста и интервалы.

Кнопка языка в шапке переключает интерфейс между RU и EN. Новые миры запоминают язык, на котором их создали, и в списке стоят в своей группе.

## Интерфейс

На широком экране меню и поле ввода видны сразу. На экране шириной до 720px меню прячется за кнопку **Меню**, а поле хода — за **Сделать ход**. Кнопки под логом прокручиваются в сторону.

### Шапка

| Элемент | Назначение |
|---------|------------|
| **Меню** | На узком экране открывает название, выбор мира и кнопки разделов |
| **Модели** | Переключение между сохранёнными конфигурациями API |
| Выбор мира | Список кампаний, отдельно русские и английские |
| **RU / EN** | Язык интерфейса |
| **Миры** | Создать, открыть, удалить, экспортировать и импортировать мир |
| **Файлы** | Текстовые файлы мира |
| **Карточки** | Редактор карточек историй |
| **Память** | Банк памяти и ручная индексация |
| **Настройки** | API, генерация, игра и тексты промптов |
| **Промпт** | Последний запрос, отправленный модели |
| **Сцена** | Промпт изображения текущей сцены |
| **Сумм.: ВКЛ/ВЫКЛ** | Автосуммаризация |
| **Память: ВКЛ/ВЫКЛ** | Банк памяти |

Рядом с переключателями видно, сколько процентов новой истории накопилось с последней суммаризации и через сколько ходов будет следующая индексация памяти.

### Под логом

| Кнопка | Назначение |
|--------|------------|
| **Сделать ход** | На узком экране показывает поле ввода |
| **Отправить** | Отправить действие. Во время генерации становится **Стоп** |
| **Дальше?** | Описать, что должно произойти, и продолжить сцену |
| **Отменить ход** | Удалить последнее сообщение |
| **Реролл** | Заново сгенерировать последний ответ мастера |
| **Редактировать** | Поправить последнюю реплику |
| **Суммаризация** | Обновить `summary.txt` сейчас, не дожидаясь порога |

Полоса под текстом показывает, сколько новой истории накопилось с последней суммаризации относительно места, которое для неё ещё есть в контекстном окне. Она желтеет ближе к порогу и краснеет, когда порог достигнут: дальше старые несуммаризованные реплики начинают выпадать из промпта.

## Остановка генерации

Пока модель работает, **Отправить** превращается в **Стоп**.

- **Ответ мастера** — уже полученный текст сохраняется в историю. Его можно отредактировать или убрать кнопкой **Отменить ход**. Фоновые суммаризация и индексация памяти после остановленного ответа не запускаются.
- **Суммаризация и память** — операция отменяется, `summary.txt` и `memory_bank.json` остаются как были. Суммаризация повторится на следующем ходе, если полоса всё ещё на пороге. Индексация памяти — через несколько следующих ходов.
- **Промпт сцены и описание карточки** — генерация отменяется, результат не подставляется.

## Промпт сцены

**Сцена** собирает промпт для картинки текущей сцены. В запрос модели попадает:

- `plot_basics.txt`, инструкции ИИ и авторские пометки
- **последние 5 завершённых ходов** — ответ мастера вместе с ходом игрока перед ним
- **релевантные карточки** по словам из этих ходов и все карточки без триггеров

Модель возвращает JSON с полями `prompt` и `negative_prompt`. Оба можно скопировать отдельно. Если JSON не разобрался, в промпт попадает сырой ответ.

Формат и визуальный стиль выбираются прямо в окне сцены и в **Настройки → Настройки игры**.

| Формат | Как выглядит промпт |
|--------|---------------------|
| **Stable Diffusion** | теги через запятую, веса `(тег:1.2)`, теги качества в конце |
| **Midjourney** | один английский абзац и параметры `--ar 16:9 --style raw --v 7` |
| **Flux** | 2–4 английских предложения, без весов и тегов качества |
| **Универсальный** | 2–4 английских предложения, без весов |

Стиль изображения дописывается в готовый промпт: без стиля, аниме, реализм, живопись или кино. У Midjourney параметры `--` остаются в конце строки.

Ключи в `worlds/settings.json`: `image_prompt_style` (`sd`, `midjourney`, `flux`, `generic`) и `image_look` (`none`, `anime`, `realism`, `painting`, `cinematic`).

## Миры

Каждый мир — папка в `worlds/`:

```text
worlds/
├── settings.json              # Настройки программы, общие для всех миров
└── Название мира/
    ├── language.txt           # ru или en — язык, на котором создан мир
    ├── ai_instructions.txt    # Как вести себя мастеру
    ├── plot_basics.txt        # Сеттинг и завязка
    ├── author_notes.txt       # Тон, стиль, пожелания автора
    ├── introduction.txt       # С чего начинается история
    ├── summary.txt            # Сжатая хроника
    ├── summary_state.json     # Сколько сообщений истории уже вошло в саммари
    ├── story_cards.json       # Карточки
    ├── memory_bank.json       # Банк памяти
    └── history.json           # История сессии
```

**Миры** умеет создать кампанию, открыть её, удалить, выгрузить zip и загрузить zip обратно. В архиве лежат файлы этого мира. `settings.json` с ключами API в архив не входит. Для импорта нужен zip именно с этими файлами.

Примеры готовых миров лежат в `Demo worlds`, отдельно `Ru` и `En`.

### Безопасное сохранение

Файлы пишутся атомарно: данные сначала попадают во временный файл, предыдущая версия копируется в `<файл>.bak`, и только потом временный файл встаёт на место. Обрыв записи не оставляет обрезанный файл вместо целого.

Если файл не читается, программа пробует `<файл>.bak`. Когда и копия битая, мир с повреждённым `history.json` не открывается: кампания не превращается молча в пустую. Банк памяти и карточки в таком случае можно собрать заново, история — нет.

## Карточки историй

Карточка — это название, описание и триггеры через запятую. В промпт хода попадают карточки, чьи слова нашлись во вводе и недавней истории. Пустые триггеры означают, что карточка активна всегда.

Описание можно написать самому или попросить модель сгенерировать его по названию.

Пример `story_cards.json`:

```json
{
  "cards": [
    {
      "id": "card_001",
      "title": "Арион",
      "description": "Арион — искатель приключений и воин. Носит кожаную броню...",
      "triggers": ["арион", "герой", "воин"]
    },
    {
      "id": "card_002",
      "title": "Таверна «Пьяный дракон»",
      "description": "Шумное заведение на окраине города...",
      "triggers": ["таверна", "дракон", "бармен"]
    }
  ]
}
```

## Банк памяти

Каждые N ходов (по умолчанию 5) модель читает новый кусок сессии и сохраняет запись: краткое содержание, ключевые слова, локацию и упомянутых NPC.

На следующих ходах в промпт попадают воспоминания, которые совпали с текущей сценой. В **Память** видно банк целиком, оттуда же можно запустить индексацию сразу.

## Суммаризация

Когда новая история с прошлой суммаризации заполняет заданную долю оставшегося контекста (по умолчанию 80%, допустимый диапазон 50–95%), модель переписывает `summary.txt`. Граница хранится в `summary_state.json` и сдвигается только после успешной записи, поэтому остановка суммаризации не обнуляет полосу.

Кнопка **Суммаризация** обновляет хронику в любой момент. Переключатель **Сумм.** отключает только автоматический запуск.

## Настройки

Всё это лежит в `worlds/settings.json`. В окне три вкладки: **Настройки ИИ**, **Настройки игры**, **Настройки промптов**.

На вкладке ИИ задаётся адрес Chat Completions, ключ, имя модели и сохранённые конфигурации. Кнопка **Модели** в шапке переключает уже сохранённую конфигурацию, не открывая всё окно.

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `temperature` | `0.7` | Креативность ответа, от 0.0 до 2.0 |
| `max_tokens` | `300` | Сколько токенов можно отдать на ответ мастера |
| `context_size` | `16384` | Окно контекста модели |
| `stream_mode` | `true` | Показывать ответ по мере генерации |
| `summary_enabled` | `true` | Автосуммаризация |
| `summary_fill_percent` | `80` | Порог автосуммаризации, 50–95 |
| `memory_enabled` | `true` | Банк памяти |
| `memory_interval` | `5` | Индексировать память каждые N ходов |
| `memory_top_k` | `5` | Сколько воспоминаний и карточек подставлять в промпт |
| `image_prompt_style` | `sd` | Формат промпта сцены |
| `image_look` | `none` | Визуальный стиль, который дописывается в промпт |
| `language` | `ru` | Язык интерфейса |
| `bind_mode` | `lan` | `local`, `lan` или `tailscale` |

Вкладка промптов хранит тексты, из которых собирается запрос: ход, суммаризация, память, карточки и сцена. У каждого текста есть обязательные поля в фигурных скобках. Если поле пропало или скобки не сходятся, настройка не сохраняется. **Сбросить** возвращает встроенный текст. Там же задаётся свой лимит токенов на ответ этого промпта. Свои тексты лежат в `prompt_overrides` отдельно для `ru` и `en`, лимиты — в `response_limits`.

## Советы

- Для длинной кампании держите включёнными суммаризацию и банк памяти.
- Места, персонажей и правила, которые должны вспоминаться по слову, кладите в карточки. То, что должно быть в каждом ходе, оставляйте с пустыми триггерами.
- **Промпт** показывает, что именно ушло в модель на последнем ходе: system, user и примерный размер в токенах.
- Конфигурации API удобно сохранить по одной на локальную модель и на внешний сервис, а переключать их кнопкой **Модели**.
